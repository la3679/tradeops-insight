# User guide

Owner: product maintainer. Purpose: explain the safe demo workflow.

The overview summarizes the deterministic dataset. Exceptions provides search/filter and status/severity cues. Open a row to see synthetic trade facts, explanation, evidence, suggested actions, graph trace, versions, and review controls. Analysts may start investigations; reviewers may resolve review interrupts; auditors inspect read-only state/audit; administrators run labelled fixture/evaluation operations.

Every mutation uses an idempotency key and can be repeated safely. If another action changes an exception first, refresh after a version conflict. Escalation is expected when evidence is absent, weak, stale, contradictory, or malicious. Knowledge shows provenance; Evaluations shows the 50-case mock baseline; Observability links metrics/health; Audit is role restricted. Keyboard focus, semantic headings/tables, labelled controls, status text, loading/error/empty/permission states, and tablet layouts are tested.
